# Scope: process misses of 2026-10-26 from 04:18, and of the night after

The maintainers build this tree with AI agents: a lead agent that plans the work, writes briefs and merges what comes back, and runs, each an agent given one brief. This table records the misses in the working process from 04:18:40 on 2026-10-26, the moment the table of the week of 2026-10-20 copied its sources, to the last landing of the night after, at 03:4x on 2026-10-27, so the two tables leave no gap between them: a brief or a preregistration that named a wrong path, judge, rule, set or generator, a ruling made before its governing file was read, a command handed on that did not run where it was run, a time written without being read from the clock, a file written or a program started outside what a run was given, a step taken against one of the maintainers' standing rules, and a command that failed because of how this machine is set up. Each row is one miss. A row describes a step and what it did, never a person; each description begins with who took the step, "the lead" or "a run", and names a run by its work in brackets.

This folder holds a bench table that records misses only. It is not a preregistered run: it has no bar, no counts and no
verdict. The bench tool requires a hashed document in the prereg's place, and this note is that document. It was written
on 2026-10-27, after the events it describes, and hashed when it was written (`SCOPE.sha256`, whose time is in UTC). It
reads NEEDS STAMP on the bench page until a timestamp authority stamps it, and a stamp can then show that the note existed
by then, and no more.

**Where the rows come from.** The lead's misses are transcribed from the maintainers' working log, which the lead writes as the work happens (its lines from 04:19 on 2026-10-26 to 03:4x on 2026-10-27, and the morning report written into it at dawn), and from the runs' reports where a run recorded a miss in a brief or a preregistration it was given. The runs' misses are transcribed from the kept-miss sections of the reports of the twenty-one runs that landed in that time (nine of the morning, four census runs, six of the afternoon and two of the night), and from the log's lines on them. Six rows were found, wholly or in part, by the run that wrote these rows, by comparing the time a report or a plan gives for its own writing with the modification time of its file. The log, the twelve reports of the afternoon and the night and two plans were copied at 07:54:46 UTC on 2026-10-27, the log while it was still being written; the modification times compared were listed from the originals in the same hour; and the nine reports of the morning were copied at 08:22:26 UTC. Each sha256 in `REPORTS.sha256` names the copy read, under a name given here. The sources name working folders and private matters on the authors' machine, so they do not ship, and the table lists them as hashed, not shipped.

**What the table counts.** As in the table of the week of 2026-10-20: every miss the log labels as the lead's own (its kept-miss and correction lines) or that a run recorded about a brief or a preregistration it was given; and every kept miss of a run that broke one of the maintainers' standing rules for runs (no version-control command; a local backup before any edit; a clock time read, never estimated; no command that names a folder the maintainers' read guard protects; scratch files where the brief allows them; a long run launched detached, not as a child of the shell), or that let a wrong result, a wrong path, a wrong count or a gap reach a record, a source file, a brief or another step before it was caught. Added in this table: a command that failed or answered wrongly because of how this machine is set up (a program name that resolves to another program, a built program that cannot find its packages without a resolution hook, a search too wide to finish within the shell's time limit, a shell tool that drops a backslash or turns an escape into a real character when a file is written through it, a detached launcher that never writes its closing line), since the next run on the machine meets the same trap; a defect a run's tests caught in what it delivered, whose fix became a declared rule of the product; a program a run started on the machine without being asked to; and a time a report or a plan gives for its own writing that is later than its file's last write by a minute or more. Not counted: an early draft, count, test or type error that a run corrected by its own reading or tests before anything used it, a general shell mistake, a note on the limits of a piece of work, a refused command or attempt that broke no rule, a step the log does not call a miss, a ruling on evidence, and a defect of a record rather than of the process. `FINDINGS.md` lists what is left out, run by run, with the reason. A line of the log written in this window about a miss the earlier table already holds is not repeated.

**How a row reads.** Hours are local time on the maintainers' machine (UTC-4); a source that gives UTC is converted. An hour written with a final x, such as 10:3x, means a time from 10:30 to 10:39, and a row whose source gives no hour says so. Rows run in time order; a row whose source gives no hour sits where its run landed. Each row is dated by the day the miss was made. Kinds: brief error (a brief named a wrong path, judge, rule or set), clock (a time written without being read from the clock), stale read (a log line written from a state already superseded), numbering (a number given from a partial read or a wrong sum), method (a step taken in the wrong order, against a standing rule, or without its check), scope (a step beyond what the run or the lead was given), harness defect (a command that failed because of the machine or the command), and defect (a defect in what a run delivered). No row is post-hoc: none was found by reading a study's results; the rows from the runs that prepared a hill's swings record their working process, not the swings' outcomes.

**Fixed.** A row carries a fix when this tree records a change that catches its class of miss (a check, a test or a refusal), in the words the fix quotes, and not before. Two rows carry one: the frontier's rule and test that read a copied hill once, and the bench harness's address check by HEAD request. The damage of most other rows was undone within the hour, and each description says how, but undoing the damage does not fix the miss. `FINDINGS.md` gives each row's status: fixed, open, or accepted (the lead ruled to leave the outcome as it is; the ledger has no such state and shows the row as open). The ledger never drops or changes a row. A fix may be added to an open row later, and a recorded fix never changes.

**What it does not count.** Misses nobody recorded and the file times cannot show, and the misses of runs that had not landed when the rows were written, which belong to the next table.
